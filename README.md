# 商品售后服务 Agent：使用说明

本项目提供本地售后演示网页，可切换客户、客服和仓库身份，办理退货退款、人工审批与工单、同款等价换货，并查询政策、物流和进度。对话理解和政策解释调用配置的真实模型；订单、物流、库存、仓库与支付均为模拟数据，不会真实寄件或付款。

- 第一次运行：按下方“安装与启动”操作。
- 想知道发什么消息、如何切换角色、预期出现什么结果：看 [售后模拟测试指南](DEMO_TEST_GUIDE.md)。
- 想了解当前与目标架构、RAG 检索方案和设计取舍：看 [项目方案](PROJECT_DESIGN.md)。

## 1. 安装与启动

以下命令使用 Windows PowerShell，在本项目目录执行。需要已安装 `uv` 和 Python 3.12 或 3.13；依赖由本项目的 `uv.lock` 管理，环境位于本目录 `.venv/`。

### 1.1 安装锁定依赖

```powershell
cd D:\CODE\hello-agents-main\after-sales-agent
uv sync --locked
```

不要在父目录创建共用环境，也不要使用 ForgeAgents 或课程仓库的环境运行本项目。

### 1.2 配置模型

在 `after-sales-agent/.env` 填写以下配置；若文件已经存在，保留有效密钥，只修改需要调整的字段。

```dotenv
LLM_API_KEY=填写本项目的中转站密钥
LLM_BASE_URL=https://rightapi.ai/v1
LLM_MODEL_ID=gpt-6.2-sol
LLM_TIMEOUT_SECONDS=120
```

`.env` 不提交到版本库。应用固定从本项目根目录读取它，显式传入模型 SDK，当前使用 Responses 接口。修改后重启服务。默认模型为 `gpt-6.2-sol`，与根目录约定一致。

关于等待时间：

- `LLM_TIMEOUT_SECONDS` 是单次模型调用的等待上限，默认 120 秒。超过上限按“模型响应超时”处理，不重试，避免再多等一个完整上限。
- 只有连接失败或中转站返回 5xx 错误、且尚未收到任何数据时，才自动重试一次。限流（HTTP 429）不重试。
- 一轮对话最多调用两次模型：办理退货、换货、查询等只调用一次（理解诉求），资格、金额和政策依据由规则代码给出；政策咨询调用两次（理解诉求 + 依据检索到的条款解释）。整轮预算随配置计算为 `2 × 120 + 15 = 255` 秒。
- 实际耗时取决于模型和中转站。开发时的实测：一次模型调用多在 5—10 秒，偶尔超过 25 秒，历史上最长约 60 秒；其中大部分时间花在等待第一段数据返回。以上都是等待预算和参考数据，不是耗时承诺，也不能改变中转站自己的限制。

其他可选配置通常不必调整：

| 配置 | 默认值（秒） | 用途 |
| --- | ---: | --- |
| `CONFIRMATION_TTL_SECONDS` | 86400 | 用户方案确认有效期，1 天 |
| `APPROVAL_TTL_SECONDS` | 604800 | 人工审批有效期，7 天 |

网页对话需要有效模型配置；下面的离线回放不需要密钥，也不会请求模型。

### 1.3 准备默认数据与政策索引

```powershell
uv run after-sales-init-db
uv run after-sales-policy-index rebuild
```

- 第一条命令创建 `data/demo.sqlite3`，按香港时区当天生成订单日期；文件已存在时保留全部记录，不重置日期、退款或库存。
- 第二条命令从政策源文件重建 `data/policy_index.sqlite3`，不调用模型，也不清空业务数据库。
- 服务首次启动会为业务库补充会话、物流、库存等表及场景。

若要从全新状态练习，加 `--reset` 重置默认库：删除 `data/demo.sqlite3` 后按当天日期重建，清空其中全部案件、退款、会话和库存预留，其他库文件不受影响。重置前先停止正在使用该库的服务，完成后直接启动即可。

```powershell
uv run after-sales-init-db --reset
```

不加 `--reset` 的再次初始化不会重置任何数据。`--db 路径` 可指定其他库文件，`--as-of YYYY-MM-DD` 可指定基准日期；独立测试库的用法见测试指南。

### 1.4 启动并打开网页

```powershell
uv run after-sales-api
```

保留该终端运行，浏览器打开：

- 网页：[http://127.0.0.1:8000/](http://127.0.0.1:8000/)
- 接口文档：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- 存活检查：[http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)

看到终端提示服务启动完成即可访问。`/health` 返回正常只表示服务存活，不代表模型已经连通。停止服务用该终端的 `Ctrl+C`；重新执行启动命令会读取原有数据，不会重新开始所有案件。

需要更换端口时，可用同一默认数据库启动：

```powershell
uv run uvicorn after_sales.main:app --host 127.0.0.1 --port 8001
```

此时访问 `http://127.0.0.1:8001/`。`after-sales-api` 自身固定使用 8000 端口，不接受 `--port` 参数。测试指南中的独立库示例使用 8015 端口，请留意网页连接的是哪个服务和数据库。

## 2. 页面如何使用

1. 首次打开时选择角色和账号，点击“使用此身份”。之后可点顶栏右侧“切换身份”更换。
2. 客户在对话框输入售后诉求，Enter 发送，Shift+Enter 换行；也可点输入框上方的示例诉求，先从“退 1 根数据线”开始练习。该示例的 33.33 元预期要求使用全新、仍在退货期限内的数据。等待回复时，输入框上方会显示当前进行到哪一步和已用秒数。
3. 回复下方会出现卡片：订单里有多个商品时，点选要办理的商品；换货缺少目标规格时，点选可用规格；出现方案后，核对商品、数量、金额和政策依据，勾选“我已核对”，点“确认此版本”，再点“提交退货申请”。确认和提交是两步。
4. 需要审批时由客服处理；无需审批或审批通过后，客户在右侧“案件详情”填写模拟承运商和退货单号。仓库在看板上登记签收、检验，客户再执行模拟退款。
5. 右侧“案件详情”显示办理进度时间线（每一步的状态、正在等待谁）和当前可做的操作；“运行轨迹”显示本轮的步骤、模型与工具调用、耗时、token 和政策引用。左侧可打开历史案件、换货和工单；客服或仓库改变状态后，点左侧顶部的刷新按钮读取最新结果。

推荐同时演示多个角色：在身份选择框底部点“在新标签页打开 客户 / 客服 / 仓库”，每个标签页各自登录一个身份，互不登出，可以同时观察同一案件在三方的变化。

| 角色与账号 | 页面能做什么 |
| --- | --- |
| 客户小林 `customer-001` | 查询本人订单、对话、确认方案、提交申请和模拟退货单号、执行或核对模拟退款 |
| 客户小陈 `customer-002` | 操作自己的订单，用于测试用户隔离 |
| 客服 `staff-001` | “审批与工单”：按待审批、待处理工单等筛选，左侧看证据、右侧填写结论，保存后自动跳到下一条；“演示控制 · 退款模拟场景”：设置退款超时等故障 |
| 仓库 `warehouse-001` | 作业看板按待签收、待检验、待换新发货、换新运输中分列，直接在卡片上登记签收、检验、换新发货和送达 |

角色选择只用于本地模拟，并非生产登录认证。在同一个标签页里切换身份会替换该标签页的会话，其他标签页的身份不受影响；刷新页面保留当前身份。“开启新对话”不清空订单、已退款额度、案件或库存。

聊天记录保留当时的回复文字；卡片上的状态和按钮按当前业务状态显示：被新版本替代的方案显示“已被新版本替代”且不再提供按钮，申请和工单卡片显示最新状态。即使有人操作了旧版本，后端也会拒绝并说明原因。“运行轨迹”只显示当前会话最近一次运行，跨会话打开旧案件不保证显示旧会话的轨迹。流式草稿以最终保存结果为准。

确认和取消优先使用卡片按钮。也可以直接说“我确认办理”“就按这个方案换货”“算了，不退了”这类明确的话；“好的”“知道了”不会被当作确认。换货方案在卡片上点“确认换货”，或在只有一个待确认换货方案时说“确认换货”；之后从左侧“我的换货”继续。

## 3. 回放与排查入口

统一场景入口不要求先启动网页服务，每次运行会建立独立业务库和政策索引，结果写入 `artifacts/replay-…/results.json` 和 `results.csv`，不会使用或重置默认演示库。

```powershell
# 列出可选场景，不调用模型
uv run python -X utf8 evals/replay.py --list

# 离线：固定模型提取结果，验证业务流程
uv run python -X utf8 evals/replay.py --mode offline --select core

# 真实模型：先选一个场景，使用 .env 配置，会产生 API 消耗
uv run python -X utf8 evals/replay.py --mode live --select normal_refund

# 独立检查组：政策咨询与他人订单隔离
uv run python -X utf8 evals/replay.py --mode live --select holdout
```

`--select` 支持场景 ID、组名以及逗号分隔选择；`core` 为除独立检查组外的十一个场景（退货退款、补问、超期、审批、转人工、故障、换货、物流），`all` 包含全部十三个场景。例如 `--select exchange,logistics` 只运行换货与物流的四个场景。离线通过不能作为真实模型理解能力的结论；检查结果中的 `passed`、最终状态与失败步骤，而不是比较回复文字是否逐字相同。

运行全部业务测试（pytest 统一入口，不调用模型、不发起网络请求，约 1 分钟）：

```powershell
uv run pytest
```

测试按业务能力分文件，可只运行其中一个，如 `uv run pytest tests/test_exchange.py`；`-k 关键字` 可按测试名筛选。
若只想检查模型接口，可显式运行以下命令；它会发起真实请求：

```powershell
uv run after-sales-model-check --mode text
```

还支持 `--mode stream`、`--mode tool` 和 `--mode all`。不必每次启动都运行全套检查。

## 4. 常见情况

| 现象 | 如何处理 |
| --- | --- |
| 提示未配置 `LLM_API_KEY` | 检查本项目 `.env`，不要把文件放到父目录；配置后重启 |
| 提示数据库或政策索引不存在 | 执行初始化、索引重建；自定义库则核对启动命令里的数据库路径 |
| 端口被占用 | 在原服务终端停止服务，或选其他端口；不要同时向同一端口启动两个服务 |
| 提示“模型响应超时”（HTTP 504） | 模型在 `LLM_TIMEOUT_SECONDS` 内没有返回结果，多为模型或中转站响应慢。本轮消息未保存、已有信息保留，输入框保留原文，稍后重发即可。经常出现时可适当调大该配置并重启 |
| 提示“无法连接模型服务”或“模型服务返回错误（HTTP 5xx）”（HTTP 502） | 已自动重试一次仍失败。检查网络、`LLM_BASE_URL` 和中转站状态，必要时运行 `uv run after-sales-model-check --mode text`。轨迹中的上游状态码和请求编号可用于向中转站核对 |
| 提示“请求过于频繁”（HTTP 429） | 中转站限流，稍等后再发送；不会自动重试 |
| 提示模型“未返回有效的识别结果”或“未返回可核对的政策解释” | 模型输出格式不符合要求，本轮未保存，重发一次即可；反复出现时记录原话和轨迹 |
| 想知道失败属于哪一类 | 打开右侧“运行轨迹”，失败的模型步骤会自动展开“模型故障”：分类（响应超时、连接失败、请求限流、上游服务错误）、HTTP 状态、请求编号、已等待时间和是否收到首个数据。服务端终端也会打印同样的分类，不含密钥和用户原文 |
| 等待回复时页面按钮暂时禁用 | 等本轮结束；输入框上方会显示进行到哪一步和已用秒数，不要反复发送同一请求 |
| 更新代码后页面空白或报模块错误 | 重启服务后强制刷新一次页面（Ctrl+F5）。服务已要求浏览器每次检查页面脚本更新，正常情况下不需要手动处理 |
| 样例突然超期、金额减少、可用库存不足 | 核对数据库是否已被使用及订单日期；新会话不会恢复这些业务数据。用独立全新库复现 |
| 明确说了商品仍被追问 | 直接点回复下方选项卡片中的商品，或补充商品项编号，如 `ITEM-002`；不要把这一现象当成已退款或已建单 |
| 提交/退款按钮没出现 | 阅读当前状态和下一步；可能尚未确认、审批、签收或检验，或原授权已过期 |
| 显示“退款待核对” | 点击“核对原退款结果”，沿用原操作；不要另建申请或更换操作编号绕过核对 |

业务规则、可复制的用户话术、完整角色切换顺序和每步预期结果见 [售后模拟测试指南](DEMO_TEST_GUIDE.md)。
